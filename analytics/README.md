# BidNow Analytics Module

Analytics documentation, event tracking specification, synthetic data context, SQL query library, and Metabase dashboard setup for the **BidNow auction marketplace** (`user_events` table in SQLite).

## Overview

This module covers the analytics layer for BidNow:

- **Event Tracking Contract (`TRACKING_PLAN.md`):** Defines event naming conventions, schema fields, nullability rules, metric formulas, and data quality invariants.
- **Data & Simulator Context:** Uses events stored in SQLite (`auction_analytics.db`, table `user_events`) generated by the local simulation pipeline (`simulator.py`), with future readiness for live frontend and backend instrumentation.
- **SQL Analytics Library (`sql/`):** Six standalone queries covering funnel conversion, category performance, daily trends, price appreciation, search behavior, and auction liquidity.
- **Metabase Dashboard:** Visual reporting layer backed by the SQL queries, exported as `dashboard_preview.png`.

## Tracking Plan & Event Schema

The complete event tracking specification is documented in [`TRACKING_PLAN.md`](TRACKING_PLAN.md).

All product and auction events are stored in a single `user_events` table using lowercase `snake_case` event names (`object_action`) and UTC timestamps (`YYYY-MM-DD HH:MM:SS`).

### Schema Columns

| Column         | Type               | Nullable | Description                                                                                                                                                      |
| -------------- | ------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `event_id`     | TEXT (Primary Key) | No       | Unique event identifier (UUID v4) used to prevent duplicate ingestion on retries.                                                                                |
| `user_id`      | TEXT               | Yes      | Authenticated user ID. May be `NULL` for unauthenticated guest activity on discovery events; required for creating listings, placing bids, and winning auctions. |
| `session_id`   | TEXT               | No       | Session identifier grouping user actions within a session.                                                                                                       |
| `event_name`   | TEXT               | No       | Event type from the event catalog.                                                                                                                               |
| `timestamp`    | TEXT               | No       | UTC timestamp (`YYYY-MM-DD HH:MM:SS`).                                                                                                                           |
| `item_id`      | TEXT               | Yes      | Listing or item identifier (`NULL` for standalone search events).                                                                                                |
| `auction_id`   | TEXT               | Yes      | Specific auction round identifier.                                                                                                                               |
| `category`     | TEXT               | Yes      | Item category (e.g., `Real Estate`, `Vehicles`, `Electronics`, `Household`, `Fashion`) or filter category.                                                       |
| `bid_amount`   | REAL               | Yes      | Starting price (`item_created`), bid value (`bid_placed`), or final winning price (`auction_won`).                                                               |
| `currency`     | TEXT               | Yes      | Currency code (e.g., `AMD`, `USD`).                                                                                                                              |
| `search_query` | TEXT               | Yes      | Search term entered by the user during `search_performed`.                                                                                                       |

### Event Catalog

| Event              | Source   | Description                                                                                                                                                                                                                                                          |
| ------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `search_performed` | Frontend | Triggered when a user submits a search query or applies a category filter. Populates `event_id`, `session_id`, `event_name`, `timestamp`, and optional `user_id`, `category`, and `search_query`.                                                                    |
| `item_viewed`      | Frontend | Triggered when a user opens an item or auction detail page. Populates `event_id`, `session_id`, `event_name`, `timestamp`, `item_id`, `auction_id`, `category`, and optional `user_id`.                                                                              |
| `item_created`     | Backend  | Triggered when a seller publishes a new auction listing. Populates `event_id`, `user_id` (seller), `session_id`, `event_name`, `timestamp`, `item_id`, `auction_id`, `category`, `bid_amount` (starting price), and `currency`.                                      |
| `bid_placed`       | Backend  | Triggered when a buyer places a valid bid (`user_id` != seller, amount rising above current bid). Populates `event_id`, `user_id` (bidder), `session_id`, `event_name`, `timestamp`, `item_id`, `auction_id`, `category`, `bid_amount`, and `currency`.              |
| `auction_won`      | Backend  | Triggered when an auction finishes with at least one valid bid and a winner is recorded. Populates `event_id`, `user_id` (winner), `session_id`, `event_name`, `timestamp`, `item_id`, `auction_id`, `category`, `bid_amount` (final winning price), and `currency`. |

## Data Simulator & Assumptions

Local analytics runs against synthetic auction data generated by `simulator.py` and stored in `auction_analytics.db` (`user_events`).

### Simulation Characteristics

- **Simulated Lifecycle:** Generates browsing and search activity, listing creation (`item_created`), sequential bid progression (`bid_placed`), and auction settlement (`auction_won`) across categories and timestamps.
- **Active vs. Closed State:** Not every auction with views or bids has a recorded `auction_won` event at the snapshot timestamp. Some listings have no bids yet or are still in progress.
- **Guest Traffic:** Unauthenticated traffic produces events with `user_id IS NULL` on discovery actions (`search_performed`, `item_viewed`), while transactional actions require an authenticated `user_id`.
- **Currency Handling:** Monetary metrics assume consistent currency filtering or normalization (e.g., `AMD`) before summing across rows.

## Metric Definitions & Data Quality Rules

### Core Metrics

| Metric                       | Definition                                                                                                                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Conversion Funnel**        | Tracks progression across `item_viewed` → `bid_placed` → `auction_won`, reporting both total events (`COUNT(*)`) and unique authenticated users (`COUNT(DISTINCT user_id)`).        |
| **Won GMV**                  | Sum of `bid_amount` strictly over `auction_won` events. Intermediate `bid_placed` amounts are excluded so outbid offers are not counted as revenue.                                 |
| **Auction Price Growth (%)** | `((final_price - start_price) / start_price) * 100`, calculated on completed auctions that have both `item_created` (`start_price`) and `auction_won` (`final_price`).              |
| **Search Analytics**         | Aggregates normalized search terms (`LOWER(TRIM(search_query))`) with total search volume, distinct authenticated users, and guest share (`user_id IS NULL`).                       |
| **Auction Liquidity**        | Measures what share of created listings (`item_created`) receive at least one bid (`bid_placed` bid rate) and what share close with a winner (`auction_won` win rate) per category. |

### Data Quality Invariants

- Every row in `user_events` must have a unique `event_id`.
- `user_id` must be non-null on `item_created`, `bid_placed`, and `auction_won`.
- Sellers must not bid on their own listings.
- Bid amounts must increase monotonically within an auction.
- Event timestamps must follow chronological order:
  ```text
  item_created <= bid_placed <= auction_won
  ```

## SQL Analytics Library

The `sql/` directory contains six standalone analytical queries.

| #  | Query                                                                | Description                                                                                                                                                 |
| -- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 01 | [`01_conversion_funnel.sql`](sql/01_conversion_funnel.sql)           | Counts `total_events` and `unique_users` across `item_viewed`, `bid_placed`, and `auction_won`, ordered by funnel stage.                                    |
| 02 | [`02_category_performance.sql`](sql/02_category_performance.sql)     | Breaks down `total_views`, `total_bids`, `auctions_won`, `avg_winning_price`, and `total_won_gmv` by category, sorted by `total_won_gmv` descending.        |
| 03 | [`03_daily_bidding_activity.sql`](sql/03_daily_bidding_activity.sql) | Aggregates `item_views`, `bids_placed`, `auctions_won`, and `daily_won_gmv` by UTC calendar date in ascending order.                                        |
| 04 | [`04_auction_price_growth.sql`](sql/04_auction_price_growth.sql)     | Computes `completed_auctions`, `avg_bids_per_auction`, `avg_start_price`, `avg_final_price`, and `avg_price_growth_pct` by category for completed auctions. |
| 05 | [`05_search_analytics.sql`](sql/05_search_analytics.sql)             | Lists top search queries with `total_searches`, `unique_auth_users`, and `guest_share_pct`.                                                                 |
| 06 | [`06_auction_liquidity.sql`](sql/06_auction_liquidity.sql)           | Calculates `created_auctions`, `auctions_with_bids`, `won_auctions`, `bid_rate_pct`, and `win_rate_pct` by category.                                        |

### Running Metabase Locally

1. Start the local Metabase JAR:

   ```bash
   java -jar metabase.jar
   ```

2. Wait until initialization completes.

3. Open Metabase in your browser:

   ```text
   http://localhost:3000
   ```

4. Connect the SQLite database (`auction_analytics.db`).

5. Create dashboard cards using the SQL queries:

   - `sql/01_conversion_funnel.sql`
   - `sql/02_category_performance.sql`
   - `sql/03_daily_bidding_activity.sql`
   - `sql/04_auction_price_growth.sql`
   - `sql/05_search_analytics.sql`
   - `sql/06_auction_liquidity.sql`

6. Arrange the dashboard cards into a clean, readable layout. Ensure that tables and charts fit the dashboard grid without horizontal overflow.

7. Capture a full-page screenshot and save it as:

   ```text
   dashboard_preview.png
   ```
